# Contributing to Spooler

Thanks for helping. Spooler is a small project, and bug reports, printer data and pull requests all
make a real difference.

## Ways to help

- **Report a bug** with the [bug form](../../issues/new?template=bug_report.yml). The end of
  `spooler.log` (Settings > **General** > **Show log file** shows its path) is the most useful thing
  you can attach.
- **Add a printer.** Most printer support starts from what the printer reports. A Moonraker
  `printer/objects/query` answer, an Anycubic MQTT report or a Bambu `pushall`, with serials and
  codes removed, lets us write a test fixture and support it without the printer.
- **Send a pull request.** Small, focused changes with a test are the easiest to review.

## The code

- `plugin/spooler/` is the plugin: the package `spooler`, one module per domain (`core.py` for settings and paths,
  `sources.py` for the Spoolman and Bambu Cloud clients, `filament_profiles.py`, `moonraker.py`, `windows.py` for the
  page bridge, `capabilities.py` for the plugin class, and so on; `__init__.py` lists them). A module refers to
  another module's names as `_core.tr(...)`, `_sources.load_spools(...)`, so a name has one home. The compiled Vue
  page sits next to the modules as `app.html`, generated by `scripts/embed_ui.py`.
- Spooler used to be one file, `spooler_any.py`, so changes from
  [Spoolio](https://github.com/danm1989/spoolio-orcaslicer) could be merged as they were. The owner chose to split
  it in 0.32.2 so Orca Cloud's automated review can finish: as one 560 KB module the review timed out on every
  publish of 0.32.1. A Spoolio change no longer merges as is. Port it by hand: find the function in the module
  that now holds it (`git grep -n "def <name>" plugin/spooler`), apply the change there, and write a reference to
  a name from another module as `_<module>.<name>`.
- `tests/` runs it outside OrcaSlicer, with a stand-in for OrcaSlicer's `orca` module
  (`tests/plugin_loader.py`) and a fake preset bundle (`tests/fake_bundle.py`). Fixtures in
  `tests/fixtures/` are real printer and Spoolman answers.
- `scripts/build.py` writes the release to `dist/`: one all-OS wheel, `spooler_any.whl`, holding the package as it
  is in `plugin/spooler/` (its modules and `app.html`).
- `scripts/store_images/render.py` renders the README and store images from the real page.
- [docs/how-it-works.md](docs/how-it-works.md) explains the presets, the sync and the files
  Spooler shares with other plugins.

## Setting up

You need Python 3.12 or newer. There are no runtime dependencies. Development also needs Node.js 24, npm and Chrome/Chromium
for the offline Vue build and browser tests, plus [ruff](https://docs.astral.sh/ruff/) for Python lint.

```sh
WORKERS=1 python -m unittest discover -s tests   # every test (page tests need Node.js 22.6+ and Chrome or Chromium)
npm --prefix ui ci && npm --prefix ui run build       # after changing the page: rebuilds it into plugin/spooler/app.html
ruff check plugin scripts tests        # lint
python scripts/check_version.py        # the two version numbers agree
python scripts/build.py                # dist/spooler_any.whl
```

CI runs the tests on Windows, macOS and Linux (x86_64 and arm64) and the lint on every pull request.

### Trying it in OrcaSlicer

Install OrcaSlicer 2.5 or later and install `dist/spooler_any.whl` from OrcaSlicer's Plugins dialog
(**File > Plugins > Install local plugin**), the same way as a downloaded plugin. Remove the Orca Cloud copy first so the two don't clash. The log is at the path Settings > **General** >
**Show log file** shows.

## Pull requests

- Add a test for the behaviour you change. A bug fix should come with a test that fails without it.
- Keep `ruff check` clean and the tests green on every OS.
- Add a line to [CHANGELOG.md](CHANGELOG.md) under the newest `Unreleased` section, in the same
  style: what changes for the person using Spooler.
- Write commits as [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `docs:` ...).
- If the page changes, re-render the images with `python scripts/store_images/render.py`.
  Build the Vue page with `npm --prefix ui run build` first. The renderer needs Node 24+ and Chrome;
  use `--out /tmp/spooler-artwork` to preserve existing artwork. Captures use mock data with network
  access blocked and fail if the page cannot render. Failure evidence is saved beside the output.
- OrcaSlicer refuses a whole preset bundle when one preset has a key it doesn't know, so only add
  preset keys that exist in OrcaSlicer's `PrintConfig.cpp` (`tests/test_profiles.py` checks the list).

## Releases

Maintainers release by bumping the version in both places (the PEP 723 block in `plugin/spooler/__init__.py` and
`PLUGIN_VERSION` in `plugin/spooler/core.py`), dating
the CHANGELOG section, matching the `ui/package.json` and lockfile versions, rebuilding the page, and pushing a `v<version>` tag. The release workflow tests, builds and opens a
draft GitHub release; publishing it uploads the build to Orca Cloud.

## Conduct

Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md).

## Privacy

Keep the owner's private setup out of source, tests, fixtures, docs, commits,
branch names, issues, pull requests and comments. Do not include machine names,
home or worktree paths, private network details, service ports or hostnames,
thread and task IDs, personal email or provider accounts, quota or credit data,
device identifiers, Wi-Fi names, or secrets.

Use RFC 5737 addresses such as `192.0.2.10`, example domains, `printer-1`,
`<serial>`, and `$HOME/...`. Keep hardware findings and redact the identifying
details. Run `sh scripts/check-privacy.sh` before submitting changes.
